# 模板使用说明

这些模板用于建立一个小型、可维护的项目入口。先补齐当前任务需要的内容，不必一次填满所有栏目。

| 文件 | 用途 | 何时需要 |
| --- | --- | --- |
| [AGENTS.md](./AGENTS.md) | 告诉助手如何工作、读取哪些规范 | 希望新任务复用项目约定时 |
| [PROJECT-README.md](./PROJECT-README.md) | 说明项目目标、入口和交付方式 | 持续维护的项目 |
| [context.md](./context.md) | 保存会影响后续任务的背景与当前状态 | 需要换会话或换设备接续时 |
| [ROUTING.md](./ROUTING.md) | 按任务目的找到唯一的规范来源 | 规范已分成多个主题时 |
| [knowledge-entry.md](./knowledge-entry.md) | 记录规则、验证依据和升级历史 | 有明确且可复用的经验时 |
| [acceptance-checklist.md](./acceptance-checklist.md) | 核对本次交付及其限制 | 涉及配置、同步或文件交付时 |

## 放到自己的项目中

1. 将需要的模板复制到项目根目录。把 `PROJECT-README.md` 改为 `README.md`，其余文件名可先保留。
2. 替换尖括号中的占位内容，删除与项目无关的栏目。没有信息时写“待确认”，不要补造内容。
3. 核对 `AGENTS.md` 到 `ROUTING.md`、`context.md` 的相对链接。移动规范文件后，同步更新入口。
4. 在一个新任务中，让助手报告本次实际读取的入口和相关规则，再做一项小任务验证。文件存在、内容已同步，都不能证明助手已经读取。

这里把规则条目放在同一目录，方便首次使用。条目增多后可以放进 `rules/` 或 `knowledge/`，但应只保留一份现行正文。其他项目通过入口引用，不再维护第二份。

## 使用边界

- `AGENTS.md` 的发现方式、层级和作用范围取决于当前工具与启动位置，使用前核对该工具的支持方式。
- `context.md` 不是通用的自动加载文件，应由项目入口明确引用，并在任务中确认读取。
- 这套文件帮助检索、复用和修正规范，不会训练模型，也不保证模型今后永不遗漏。
- 知识文件同步不等于会话历史同步、侧边栏项目同步或云端绑定同步。这些状态需要分别核验。
- 模板不需要定时任务、后台模型调用或运行状态数据库写入。公开分享前，仍要检查正文、附件和 Git 历史。
