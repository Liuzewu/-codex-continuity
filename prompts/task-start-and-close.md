# 任务启动与经验收尾

用于需要复用项目背景、继续旧任务或维护规范的工作。将占位内容替换为本次实际信息。

```text
本次目标：<要交付的结果>。
新增信息：<相对已有背景发生了什么变化>。
输入材料：<位置与版本>。
约束与停止条件：<权限、预算、截止和必须保留的内容>。

开始时：
1. 核对当前工具支持的项目指令加载方式。读取项目入口，按用途找到本次相关的现行规范；如果 context.md 被入口引用，再读取其中的必要部分。报告实际读取的文件，不假定文件存在就已生效。
2. 明确交付物和验收方式，检查关键资料是否齐全。只对无法推断且会显著改变结果的问题提问，其余在已授权范围内继续。
3. 保护已有修改，选择最小、可恢复的执行路径。不要为补全流程增加后台模型、定时任务或内部状态写入。

结束时：
1. 交付完整结果，说明实际验证、未覆盖范围和剩余限制。成功标准以行为和交付物为准，不能用计划或自评替代。
2. 判断本次反馈是否值得复用。将新要求或失败经验先视为候选，确认适用范围是本次、单个项目还是共享规范；一次例外不要自动扩大。用户已明确范围时不重复确认，范围有实质歧义时再询问。
3. 在已有维护授权内，把适用内容写回唯一的现行来源，保留必要升级记录，更新入口并回读差异。没有可复用信息就不新增总结文件；未验证做法保留为候选。
4. 简短说明哪些已保存、哪些待同步、哪些已在目标设备回读。不要把规范复用说成模型训练或永久记忆，也不要保证以后永不遗漏。

如果知识来源不可访问，说明缺口，不用旧聊天覆盖新版正文。正式记忆、外部发布及权限变更继续遵守各自的授权边界。
```
