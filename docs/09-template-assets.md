# 模板资产沉淀：规则与交付分开保存

这是一份匿名归纳复盘，不是原始事故记录。示例是全新通用骨架，没有引用私人原件，也没有代表任何文件完成验收。它适用于整理可复用的文档制作方法。

一次交付得到认可后，先确认哪些要求值得保留。稳定约束可以是内容顺序、必须保留的字段、可编辑范围、输出格式，以及如何证明结果符合要求。某次任务采用的具体值、临时例外和未确认建议，应留在该次任务中。一次成功不足以说明所有软件和设备都能得到同样结果；没有验证过的环境继续标为待检查。

规则、任务参数、原件和渲染验收分别承担不同作用。规则说明允许怎样制作，任务参数提供本次填写内容，原件用于核对来源，渲染验收记录实际打开后的结果。把它们分开，后续就能更新规则而不覆盖原件，也能更换参数而不沿用上次的验收结论。参数值改变、内容变长或模板修订后，应重新检查受影响的部分。

用户确认的反馈，应回到唯一规则来源维护：写清要求、适用范围和必要例外，再回读确认。其他入口只引用该来源，避免把旧聊天摘录维护成另一份规则。本次专用要求不自动升级为通用规则；范围仍不清楚的反馈先保留为待确认项。修改前保留可恢复版本，并说明本次改动依据。

原件留在受控的私有位置。公共模板只保留字段名称、填写说明和空值，不复制个人数据、合同条款或完整私人模板。删除正文中的识别信息后，还要检查文件名、批注、修订、属性及引用是否带入来源线索。公共骨架无需展示真实路径；需要追溯时，在私有任务记录中维护对应关系。

下面的 JSON 仅定义字段组织方式，没有附带校验器。空字符串表示未填写，空对象表示尚无任务参数；这些状态都不代表不适用或已完成。公开版本中的原件与证据引用保持为空，不填写真实位置。状态默认待检查，不能根据文件存在或脚本执行结束自动改成通过。

```json
{
  "asset_name": "",
  "purpose": "",
  "rules_ref": "",
  "task_parameters": {},
  "original_ref": "",
  "structure_status": "待检查",
  "structure_evidence_ref": "",
  "render_status": "待检查",
  "render_application": "",
  "render_environment": "",
  "render_evidence_ref": "",
  "change_note": "",
  "previous_revision_ref": ""
}
```

对应的 Markdown 头部使用同名字段。它是另一种记录形式；实际维护时选定一份主记录，其余由它生成或引用，避免两份状态各自变化。

```markdown
---
asset_name: ""
purpose: ""
rules_ref: ""
task_parameters: {}
original_ref: ""
structure_status: "待检查"
structure_evidence_ref: ""
render_status: "待检查"
render_application: ""
render_environment: ""
render_evidence_ref: ""
change_note: ""
previous_revision_ref: ""
---
# 【待填写：模板名称】
```

结构检查只能核对字段是否齐全、类型是否符合约定、引用是否可解析。它不能证明正文准确，也不能代替在目标 Word／Office 环境中实际打开文档、逐页查看、按交付要求导出并检查结果。渲染记录应说明所用应用、环境和证据；没有实际检查，就保留待检查。本页没有声称做过跨端或 Office 验收。结构检查和渲染验收都不是法律审查，本页也不提供法律建议。

最少落地步骤：

1. 从已确认的交付要求中提取稳定约束，指定唯一规则来源，记录仍待确认的事项。
2. 新建空白骨架，用明确占位内容试填；原件及其对应关系继续留在私有位置。
3. 分别完成结构检查与目标环境的渲染检查，记录真实结果和适用范围，再决定是否用于后续任务。

发现来源不明、公共文件混入私人内容、引用失效或渲染异常时，停止发布和复用，保留待检查状态。修订有问题时恢复上一份已保存版本，同时保留本次参数与问题记录；旧版本的验收结论不能直接移给新文件。需要改变权限、上传原件或覆盖唯一副本时，先停在该边界，按实际授权处理。
