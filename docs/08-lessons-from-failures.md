# 从失误中保留下来的工作方法

本文是对维护经验的匿名归纳复盘，不是原始事故记录。相近问题按类型合并，省略时间线、身份、路径、内部标识和原始日志。这里提炼的是可复用的判断方法；没有完成验收的部分仍保留为未知。

这些问题有一个共同点：一个看起来正确的信号，容易被当成整件事已经成功。减少这类失误，需要先说清要验证哪个对象，再为它找直接证据。

## 1. 根据标题猜归属，批量移动会话

**现象：** 整理后侧边栏看似整齐，却有会话离开原来的项目；标题与实际交付用途并不一致。

**错误捷径：** 按标题关键词一次性归类。标题可能沿用早期问题，也可能只概括某一轮讨论；一个会话还可能跨过多个主题。相似标题不能证明应归同一项目。

**更稳做法：** 先核对会话的实际结果、关联材料和现有归属，形成小份候选清单。目的清楚的先处理，含混的保留原位。先移动少量会话并回读，确认没有丢失上下文，再继续下一批。

**证据与边界：** 归属列表、实际材料和必要的历史片段可以相互核对。单凭标题或摘要不够；无法确认用途时，应记录“待判断”，不能把猜测写成已确认分类。

## 2. 显示归属正确，误以为工作目录也已改变

**现象：** 会话已经显示在目标项目下，但后续命令仍从旧目录开始，或继续引用旧入口。

**错误捷径：** 把“移入项目成功”当成目录迁移完成，再据此删除旧目录或兼容链接。

**更稳做法：** 分别核对项目归属、登记根目录、会话的默认工作目录和实际命令使用的路径。不同路径还可能指向同一实体，需先辨明链接关系。界面整理与文件迁移分别处理。

**证据与边界：** 列表回读证明归属，目标任务中的实际输出证明执行位置，文件检查证明材料可达。手机与桌面归类不一致时，先记录实际显示及入口身份；不能据此断言它一定按 `cwd` 分类，也不能把尚未验收的显示问题写成已经根治。

## 3. 整理本地入口时，忽略云端关联

**现象：** 本地文件仍在，项目入口却受到关联状态影响；改显示名、移分区和解除关联的结果被混在一起。

**错误捷径：** 为了去掉关联，直接删除云端对象，再观察本地是否恢复正常。这样可能同时改变入口和资料关系，恢复范围也随之扩大。

**更稳做法：** 先确认对象类型及关联关系，单独记录本次到底要改哪一项。通过当前产品支持的入口操作；无法确认关联影响时，保留现状，继续完成独立的整理工作。

**证据与边界：** 本地文件存在，只能证明文件还在；它不能证明云端资料、项目身份或跨端入口完整。云端不可访问也不等于已经删除，更不能单凭错误提示判断删除者或原因。

## 4. 同步成功，误以为新任务已经应用规则

**现象：** 两份知识文件内容一致，新会话却仍沿用旧做法，或根本没有读取相关正文。

**错误捷径：** 把同步工具返回成功、文件哈希相同，直接写成“跨设备经验已经生效”。

**更稳做法：** 分两步验收。先比较明确选定的知识文件，再在目标设备的新任务里核对规则入口，并用一个小任务验证它是否按现行规范执行。将文件一致、正文已读取、行为已验证分别记录。

**证据与边界：** 文件比较不能证明模型实际读取，更不能证明输出质量。没有新任务中的应用证据，就只报告文件一致；不要从中推导侧边栏、会话历史或应用状态也已同步。

## 5. 一次可达，误以为可以长期稳定使用

**现象：** 一次远程命令执行成功，换一个时间或设备状态后却超时。界面显示在线，也未必能完成实际任务。

**错误捷径：** 成功一次便宣布连接稳定；失败一次便认定机器睡眠、需要解锁，随后反复重启或重新配对。

**更稳做法：** 先核对目标设备，区分连接状态、界面响应和实际执行结果。只针对当前用途做有界测试，记录测试时的设备状态、输出及退出码；新现象出现后再补对应测试。

**证据与边界：** 一次执行成功只覆盖当次条件。未测试的锁屏、系统睡眠、唤醒和重启后首次解锁仍是未知。超时本身不能证明根因，也不能用一次成功掩盖后续失败。

## 6. 刚改完就收尾，遗漏旧关联再次写回

**现象：** 修改后首次回读正确，稍后刷新或重新打开界面，旧名称或旧关联又出现。

**错误捷径：** 不断重复同一修改，或为了让显示立刻一致，直接改内部数据库和缓存。这样会让原来的问题与新的修改混在一起。

**更稳做法：** 暂停重复操作，确认是否还有旧会话、旧入口或其他设备在持续保存关联。通过支持的界面完成一次小改动后，留出与实际保存行为相符的观察窗口，再回读并核对界面。必要时由使用者保存工作、正常关闭相关入口后重试。

**证据与边界：** 需要观察修改是否保持，以及重新进入后是否仍一致。短暂正确只能算中间状态；未确认写回来源时，保留“原因未定”，不要许诺某个固定等待时长就能解决，也不要把内部状态改写当作公开修复步骤。

## 把教训用到下一次任务

开始前，写清本次结果、相关对象和停止条件。执行中每批只改必要范围，保留可恢复依据。收尾时逐项写“实际通过、仅核对配置、尚未验证”，而不是给整件事一个笼统的成功标签。

只有经过实际核验、能在同类任务中复用的方法，才进入现行规范。未解决的现象保留原有边界；恢复前先比较新增成果，避免旧副本覆盖已经完成的工作。
