# 如何理解这里的验证结果

本仓库提供可复用的方法，没有把一套私人环境的配置原封不动搬出来，也没有声称替读者完成了安装或三端验收。

## 三类陈述分开看

| 类型 | 在本文中的含义 | 不能推导什么 |
| --- | --- | --- |
| 官方产品行为 | 在 [来源说明](SOURCES.md) 中列出的官方页面支持该描述 | 所有版本、平台和账号均已开放 |
| 实践中归纳的方法 | 从维护经验中提炼的顺序、检查项和约束 | 读者照做后必定得到相同结果 |
| 本仓库工具的测试 | 临时虚构文件上的具体输入和输出通过测试 | 已在读者设备执行、所有隐私已消除 |

## 目前明确保留的限制

- 模板需按任务读取和验证，不能保证模型永不遗漏要求；单纯复述规则不等于交付达标。
- 知识文件一致，不代表本地项目列表、历史会话、侧边栏和云端绑定一致。
- 手机能继续主机任务，不代表它采用与桌面相同的列表分组。手机归类不一致的具体原因不能仅凭工作目录推定。
- 一次远程调用成功，不构成长时间可用性的证明。合盖、睡眠、重启、网络变化和应用退出是不同条件。
- 字节一致只覆盖本次明确选择的文件；不证明整个目录、所有模板依赖、源资料及模型行为一致。
- 只有在各目标系统实际运行测试后，才可声称该平台通过。提供跨平台写法不等于完成跨平台实测。
- 自动化同步容易遇到未保存编辑、并发修改、同文件冲突和路径差异。本仓库先提供人工流程及只读比较，不附带自动部署脚本。
- 本仓库的文本检查只是启发式辅助。敏感语义、图片、Git 历史和未知凭据必须另行检查。

## 写一条合格的验收记录

记录“在什么条件下，检查了什么，实际看到了什么”，然后说明尚未覆盖的情况。例如：

> 在两个练习目录中比较 `standards/` 和 `ROUTING.md`，退出码为 0，所选文件字节一致。未连接其他设备，未比较应用数据，也未执行真实文档任务。

不要把这条记录改写成“三端已经完全同步”。
