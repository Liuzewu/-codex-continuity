# 项目与侧边栏整理：先分清对象，再改归属

本篇适用于长期使用 Codex 后，项目、会话和文件入口开始难找的情况。目标是让同一用途的工作回到稳定入口，保留历史材料和恢复路径。本文的四区结构和命名是推荐示例，不是应用限制；产品能力参考截至 **2026-10-25** 的[官方项目文档](https://learn.chatgpt.com/docs/projects)。

## 先分清六个概念

| 概念 | 含义与边界 |
|---|---|
| 侧边栏分区 | 组织项目和会话的显示位置；分区不是磁盘父目录。 |
| 项目 | 应用中的工作入口。本地项目关联工作目录，云端项目承载其支持的资料和上下文；显示名可以不同于文件夹名。 |
| 会话归属 | 会话显示在哪个项目下。重新归类不能作为工作目录已改变的证据。 |
| 工作目录 `cwd` | 会话记录的默认工作目录；具体命令可显式使用其他路径，它也不是访问权限边界。 |
| 实体目录与兼容链接 | 不同路径可能指向同一份文件；删除旧路径前，需要确认链接及仍在使用它的引用。 |
| 云端关联 | 本地入口与云端对象的关联关系。它与远程控制、SSH 连接及知识文件同步分别管理。 |

文件面板、文件夹选择器和项目侧边栏是不同入口；其名称或路径不能代替项目登记信息。查问题时，把显示名、对象身份、目录和归属分别记下来，不凭相似名称判断是同一个对象。

## 用四个分区承接长期用途

推荐采用“大分区 → 固定项目 → 按结果命名的会话”。项目用统一的英文 Title Case，分区用便于浏览的中文。下表每区给出六个可选方向，按真实需要保留，不为凑数量创建空项目。

| 分区 | 可选项目方向 |
|---|---|
| 商务工作 | Business Development（业务拓展）、Customer Success（客户协作）、Contract Review（合同审阅）、Tender Preparation（投标准备）、Commercial Operations（商务运营）、Weekly Reports（工作报告） |
| 系统运维 | Device Administration（电脑与设备）、Network Operations（网络与接入）、Server Operations（服务器与集群）、Codex Operations（Codex 与工具）、Backup and Recovery（备份与恢复）、Security Maintenance（安全维护） |
| 智能计算 | Model Evaluation（模型评估）、Inference Services（推理服务）、GPU Planning（算力规划）、AI Applications（AI 应用）、Data Workflows（数据处理）、Technical Research（技术研究） |
| 个人成长 | Career Planning（职业规划）、Interview Preparation（面试准备）、Learning Notes（学习笔记）、Writing Practice（写作练习）、Personal Projects（个人项目）、Life Administration（生活事务） |

项目承担持续用途，会话承担具体结果。例如在 `Server Operations` 中分别处理一次巡检、一次容量评估和一次变更复核。一次性问答可以不建项目。

## 最少整理步骤

### 1. 先盘点，不急着搬目录

读取当前项目和会话列表，核对应用界面中的显示名、所属设备、根目录及云端关联。记录拟修改对象、目标位置和恢复依据；真实路径和内部标识留在私有记录中。

对同名、重复或缺失入口，先检查实体目录是否存在、两个路径是否指向同一实体、会话是否仍引用旧入口。界面分类混乱不一定需要搬文件。

### 2. 为新工作选定稳定主目录

本手册建议：一个 Mac 本地项目选一个固定主目录，同用途的新会话复用它。已有多根目录项目应先保留，确认依赖和产品支持的迁移方式后再调整，不能把建议当成强制单根限制。

目录只保留必要入口：`README.md` 说明用途，`AGENTS.md` 说明执行约束，资料索引指向原件和现行规范。持续任务按需维护少量上下文，不复制第二套规范，也不生成大量空总结。

### 3. 先整理显示，再处理文件迁移

使用当前应用提供的改名、移动分区或调整会话归属入口。先选一个低风险项目做小批试改，立即回读结果，再处理其余项目。工具缺少某个编辑能力，不代表应用界面一定没有对应功能，应分别核实。

若确实需要移动文件，单独列出源目录、目标目录、引用和回退办法。只使用支持的操作方式；不直接编辑内部数据库、运行缓存或未知配置来“修正”显示。兼容链接在旧引用处理完且实际验收通过前继续保留。

有云端关联的本地工作区按实际用途整理，纯云端项目按其资料组织方式管理。改名、移动分区和解除云端关联是不同操作，不能通过删除云端对象来试探解绑效果。

## 验收要覆盖实际使用入口

每批改动后，分别核对以下结果：

1. 支持的接口或列表回读与预期一致；桌面分区和项目显示正确。
2. 根目录指向预期文件；会话归属正确，实际 `cwd` 已核实。
3. 文件能读取，必要时保存并重新打开一个测试文件；已有内容未被覆盖。
4. 若会从手机或另一台电脑进入，再检查对应入口及实际任务执行位置。

知识文件同步只证明所选文件完成同步，不能证明侧边栏、会话记录、项目归属或应用状态也已同步。[远程连接](https://learn.chatgpt.com/docs/remote-connections)同样需要单独验证，不能用目录整理结果代替。

## 停止、回退与未解决边界

遇到对象身份不清、根目录缺失、归属回读不一致或关联状态无法确认时，停止扩大修改。保留当前记录和已有文件，先定位差异。回退前比较整理后新增的成果，按项恢复，避免旧备份覆盖新内容。

若手机与桌面的项目归类不一致，先记录两端实际显示文字、入口和对象身份；原因未明时保留现状。仅凭工作目录差异不能推定客户端如何分组，桌面归属正确也不能证明手机已经修复。没有逐项核对手机入口身份和实际行为前，不提供“删掉旧目录就能解决”的结论。

最常见的误区是把分区当文件夹、把改名当迁移、把路径相似当同一项目，以及把一次接口成功当作全部设备验收通过。按对象逐层核对，通常比反复重建项目更容易保住原有工作。
